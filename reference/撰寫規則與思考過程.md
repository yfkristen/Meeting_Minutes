# PMO會議記錄撰寫：思考過程與規則演化

這份文件記錄從這個對話裡歸納出來的規則，以及每一條是怎麼被退出來的。

---

## 一、基本結構

從 7/23 定稿確立：

- 壹會議時間／貳與會人員／參討論議題與會議紀要
- 名單沿用前次，每場只更新出席狀態（誰請假、有無新增列席）
- 日期按雙週週四推算；結束時間逐場問
- 郵件前後有固定套語：「各位主管好：檢送⋯⋯敬請參閱」與「若有任何問題，再請聯繫我，謝謝！Best,」

三節的分工從實際定稿歸納：
- 一、本次主議題（另外邀請單位列席那一項）
- 二、各案進度（Loop看板既有案件，案名照看板）
- 三、新增議題（本次新冒出、尚未進看板）

---

## 二、壓縮比與選材

7/23 逐字稿約9,000字，定稿約500字，壓縮比18:1。

**選材原則**：只寫本次產生新資訊的。逐字稿提到11項交辦事項，定稿只列5項。

**不入錄的類別**（每一條都有被退的實例）：

| 類別 | 實例 |
| --- | --- |
| 承辦內部作業 | 幾點進場、派幾名同仁、現場備用機給誰 |
| 執行過程細節 | 主持與計時分工、報告人提交時程 |
| 評價語 | 「很崩潰」「一定覺得很好用」 |
| 工具即時排錯 | WiFi、API key、插線問題 |
| 會前與散會後談話 | 等人到齊前的公有雲閒聊 |
| 無結論的討論 | 只到「還在討論」、沒有下一步 |
| 具體到讀者用不上的數字 | 900人、電話號碼、93頁 |

**保留的**：
- 決定（有誰承接）
- 未決（卡在哪一關、下一步是什麼）
- 有時間節點的里程碑
- 構成結論的理由（例如Slack三項不採用的事實）
- 前提條件（例如主管須於會前下載簡報，否則當天進不去）

---

## 三、不得推論

這是被退最多次的一條，最後寫成最高優先規則。

**凡逐字稿沒有明說的，一律不寫；寧可漏，不要補。**

實際犯過的錯：

| 錯誤 | 來源 |
| --- | --- |
| 把8/6的API Key寫進9/3的帳號設定 | 把別場的內容搬過來 |
| 「銀行設備均已安裝完成」 | 逐字稿只說「沒有特別回報說行不行」 |
| 委外報備具名到葛世豪 | 逐字稿判斷不出說話者 |
| 委外三要件寫成決議 | 當天停在「要有人去認定」，無結論 |
| 「送松山升級並驗證資料移轉」 | 移轉是另一件未定的事 |
| 把Kevin老師對應到授課段落 | 逐字稿全篇無「Kevin」 |

四種最容易被補的：歸屬、對象、原因、數字。

---

## 四、語體

行政文書體。正式動詞優先：已／業已／刻正／俟／惟／擬／另。

**被退的句式**：

| 退掉的 | 改成 |
| --- | --- |
| 交辦管道眾多，導致資訊碎片化 | 專案推動涉及多元溝通與交辦管道 |
| 避免漏接交辦事項 | 定期彙整重要事項、同步執行進度 |
| 功能比較由張老師負責 | Slack與Teams功能比較由張老師負責 |
| 就看你們要什麼時候寄 | 不寫（無結論） |
| 自己放 | 請各位自行新增 |
| 先把檔案丟入群組 | 可先將檔案於群組中分享 |
| 「請團隊」「由承辦掌握」 | 拿掉（我加的，逐字稿沒有） |

**三條用詞原則**：
- 問題診斷改正面表述（漏接→彙整、分歧→一致）
- 管控語彙改協作語彙（追蹤機制→同步機制）
- 不寫削弱義務的表述（「並採開放參加性質」被刪）

---

## 五、交辦句式的條件

主議題節有時用「請⋯⋯」，但有前提：**當場有人承接、事情已定案**，才寫成交辦。沒到這一步就寫陳述式（「已」「將」「待」）。

紀錄沒有立場指派工作。

---

## 六、敏感詞去識別

| 原始 | 紀錄 |
| --- | --- |
| 中國模型 | 境外模型 |
| 南京子行 | 海外子行 |
| 證券參訓設備 | 採租賃的電腦設備 |
| 寬董 | 金控董事長 |

注意：「證券」在描述設備歸還時去識別，但在描述設備升級風險時具名（因為那是風險所在）。使用者決定，不是硬規則。

---

## 七、案件的取捨

- 案名照Loop看板，可精簡但不自創
- 無實質內容者整項刪（不寫「本次未討論」）
- 負責人依案件歸屬，不依當日出席（請假者仍標名）
- 不在看板的新事項另立「新增議題」節

---

## 八、里程碑的寫法

追蹤表用、不在紀錄正文。

- 留有日期的節點（例如8/28討論、12月公告）
- 點出排程限制的實質原因（例如「科技運用管理委員會非定期召開，各階段時程須提前規劃」）
- 不逐一列出每一道核決關卡
- 不寫「須注意里程碑時程」這種沒有依據的提醒

---

## 九、紀錄與追蹤表的分工

| 維度 | 會議紀錄 | 任務追蹤表 |
| --- | --- | --- |
| 讀者 | 各位主管，逐次寄送 | PMO內部，跨會議累積 |
| 範圍 | 本次產生的內容 | 全部案件，含本次未動者 |
| 寫什麼 | 為什麼這樣定、有哪些前提與理由 | 走到哪一關、下一步、時限 |
| 未討論的案 | 整項不出現 | 標「本次未討論／維持前次」 |
| 密度 | 一至三句，可含理由 | 一至兩句，只留狀態與節點 |

---

## 十、體例硬規則

- 標點全形（逗號、分號、冒號、句號）；括號半形
- 不用破折號「——」，改用句號、逗號或冒號重組
- 議題底下只用 1. 2. 3.，必要時再往下一層用 (1) (2)
- 不下「痛點」「決策」這類分類標籤
- 標題不出現評價語（「高風險」「危機」）
- 無主詞時用書面動詞起句：已建立、已完成、尚待、將安排
