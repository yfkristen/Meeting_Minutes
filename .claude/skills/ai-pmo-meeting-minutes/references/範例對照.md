# 範例對照：2026/7/23 PMO 例會

一組完整的逐字稿與定稿對照。原始逐字稿約 9,000 字，定稿約 500 字。

## 輸入條件

- 語音轉檔，**無說話者標記**
- 每字之間插入空白
- 英文產品名、機構名大量誤轉
- 會議名稱、時間、與會人員名單由使用者另行提供

## 逐字稿代表性片段（已移除字間空白）

**片段一：運作機制**

> 我們現在在那個 Teams 裡面的聊天裡面就新增了一個這個 loop。那實際上面就是其實我覺得它沒有超級好用，但它也沒辦法太克制化，所以我現在只是就是把工作的項目打上去，然後還有指派人，那大家如果陸續收到有什麼工作大家覺得要放上去都可以自己放……因為大部分的工作長官呢都很好心，都沒有幫我們壓任何到期，所以現在都空白……然後只有那個是已經我已經焦卷，所以就給他直接壓完成

**片段二：會議目的（散落於中段多處）**

> 我覺得因為我覺得現在對我言資訊很很多分亂七八糟。我就是覺得資訊太多，所以才說要開各式各樣的會議中溝通一下。可能 A 會議中也講一下這個議題，B 會議中也講一下這個議題，然後傳出來的資訊可能其實是不一樣的……我從 A 管道拿到一個資訊，因為時間是趕的，大家就會趕快依照 A 管道怎麼做的東西開始做，做了一半或做到這不是要做的，其實 B 管道來的資訊可能不是這樣，因為後來什麼會議又改了

**片段三：Slack 評估**

> 我這邊還有另外一個工作是那個 SAK 在企業環境內的限制，那這個主要是因為被交辦一個說 sake 這麼好用，那為什麼公司不全部改用 sake 不用 s?那這個題目我們就分成兩部分準備，那張老師說他那邊會準備 S 跟 TS 的功能比較。但因為那一定會很我都可以想像那個東西會寫怎麼，一定會覺得 S 很 fancy 又很好用……他現在在台灣是沒有任何機房，然後他們有說他們會申請準備，但是他現在台灣沒有落地機房，然後台灣的金融業也沒有做申請，那所有的 Slake 的資料反正就是儲存在境外，所以它在境外委外的這一塊的法規應該就是會有些遵循的困難，不會說不可能，但是就是有重的困難，所以我們在合規面這邊就會建議不要，但是老師可能就會說，哦這個真的很好用，那這些整份報告怎麼樣，我們就再再說，那這一份的話今天是已經交給老師這邊

**片段四：會議頻率（出現於逐字稿結尾）**

> 然後我們目前就是說雙週。可以耶，可以耶……我說那個雙週開一次會嗎?對，就這個頻率可以啊……就是交流一下進度，然後如果沒有時間的話，我們就是人可以 skip，這是 open 的沒有線要

**片段五：完全不入紀錄的內容**

> 他們交事情的工作群就有三四個不同的，我有 LINE，有 s 的，然後還有個人的，有一個主管，有兩個主管，有三個主管。真的我們真的很崩潰
>
> 每一次都會有人要拿各種 AI 來侮辱大家……我說不需要，我不要把垃圾再丟給大家，真的
>
> 我覺得 TR 最近不太穩，他有時候會整天掛掉……然後掛掉看起來顯示是 API key，所以我想說你可以幫我問一下
>
> 我們上次說 Slack 要在那個 wifi，至少在內網 WiFi 環境可用……我在插線才可以，我只能插線才能用呢，我好可憐

第五組片段涵蓋四類排除項：抱怨、對文件品質的評價、工具即時排錯、個人使用問題。其中工具排錯雖產生了「請資訊單位查 API key」這類小型請託，仍不入紀錄，因為未達交辦事項層級。

## 對照要點

- **議題二**（會議安排）在逐字稿結尾才出現，定稿放在第二項。排序依制度層級，不依發言順序
- **議題三**的內容散落在逐字稿開頭與中後段至少三處，全部歸攏為一項
- **片段一**中「我覺得它沒有超級好用」「長官都很好心」屬評價與反諷，全數移除，只留機制事實
- **片段三**約 400 字壓縮為 3 句。保留三項構成結論的事實，移除對張老師報告內容的預判
- 逐字稿討論到的交辦事項編號達 11 項，定稿只列 7 項。**僅本次產生新資訊者入錄**

## 報告與討論的分類依據

以本場會議逐項說明判準的實際套用：

| 案件 | 分類 | 依據 |
| --- | --- | --- |
| AI 工作坊模擬題目 | 報告 | 單向陳述，狀態明確，無人提出意見 |
| Slack 企業環境評估 | 報告 | 評估已完成並交付，為既成事實 |
| 8月課程規劃 | 報告 | 有問答（150 分鐘是否含 demo、可否提早下課），但答覆未改變任何安排，不構成新資訊 |
| 資料分級/郵件管理 | 討論 | 兼具認知落差、權責重新界定、未決三項 |
| 工作坊執行方式 | 討論 | 做法變更：取消當天抽籤改事前分組 |
| Slack 後續走向 | 討論 | 未決：合規建議與功能比較尚未整合 |
| 個人 API key 管理 | 討論 | 未決且無時程，但已在追蹤清單上，故列入並註明尚無結論 |

最後一項在原始採用版中未列。設置討論事項節之後，「已在追蹤清單上但尚無結論」的案件有了歸屬，不再因無結論而整項省略。

Slack 一案在原始採用版中為單一項，「後續走向待議」附於報告句末。區隔之後拆為兩處：已完成的評估屬報告，未決的採用決策屬討論。這是「同一案件兼有報告與討論」的例外情形：因兩者可各自獨立成立且指向不同承辦，故予拆分；一般情形仍應整案歸入討論事項。
