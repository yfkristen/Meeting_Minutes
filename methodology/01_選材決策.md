# 選材決策

## 唯一判準

**本次是否產生新資訊？** 產生了才寫。

壓縮比約 18:1（7/23 逐字稿約 9,000 字 → 定稿約 500 字）。逐字稿提到 11 項交辦事項，
定稿只列 5 項。會議紀錄的讀者是各位主管、逐次寄送，看的是本次產生了什麼；
要看全部案件狀態的是任務追蹤表，不是紀錄。

## 決策順序

對逐字稿中的每一個事項，依序問：

1. **本次有沒有新進展？** 沒有 → 整項刪除，不寫「本次未討論」。
2. **有沒有結論或下一步？** 兩者皆無、只停在「還在討論」→ 不收。
   有下一步但無結論 → 收，並寫明「本項尚無結論，將……」。
3. **讀者會因此做什麼或知道什麼？** 不影響任何人行動、也不構成理由 → 不收。
4. **是承辦內部作業或執行細節嗎？** 是 → 不收。

## 保留

| 類別 | 說明 |
| --- | --- |
| 決定 | 含承接人 |
| 未決 | 卡在哪一關、下一步是什麼 |
| 里程碑 | 有時間節點者 |
| 構成結論的理由 | 例：Slack 不採用的三項事實（境外儲存、無落地機房、委外遵循困難） |
| 前提條件 | 例：主管須於會前下載簡報，否則當天進不去 |

## 不收

| 類別 | 實例 |
| --- | --- |
| 承辦內部作業 | 幾點進場、派幾名同仁、現場備用機給誰 |
| 執行過程細節 | 主持與計時分工、報告人提交時程 |
| 評價語 | 「很崩潰」「一定覺得很好用」 |
| 工具即時排錯 | WiFi、API Key、插線問題 |
| 會前與散會後談話 | 等人到齊前的閒聊 |
| 無結論的討論 | 只到「還在討論」、沒有下一步 |
| 讀者用不上的數字 | 900人、電話號碼、93頁 |
| 對人的評論與人事臆測 | 一律不收 |

## 判例

- **「先不會有結論」**：9/17 跨部門共用 skill 審查層級，討論半小時後明確收在
  「我們先不會有結論」。可寫的只有「本項尚無結論，將另安排會議與三長及兩位窗口對焦，
  須於九月底前完成」；討論中出現的「改以採用率觸發定期檢視」只是提議，
  寫成「建議」已屬推論。
- **結案案件**：強化外寄郵件管控機制於 9/17 確認無須增列管控事項，
  寫「現行管控機制已無須增列，於月底會議回報後結案」，而非整項刪除——
  結案本身就是本次產生的新資訊。
