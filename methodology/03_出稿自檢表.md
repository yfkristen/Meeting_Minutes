# 出稿自檢表

送出前逐條核對。**第一組過不了就退回選材重做**，不要在文字上修補。

## A. 不得推論（最高優先）

> **凡逐字稿沒有明說的，一律不寫；寧可漏，不要補。**

- [ ] **已逐句列出逐字稿原文依據**（不是用讀的判斷，是實際指出原文）？
- [ ] **歸屬**：負責人、承接單位是逐字稿說的，不是我從案件性質推的？
- [ ] **對象**：誰要求、向誰報告，是逐字稿說的？
- [ ] **原因**：「主因……」「因涉……」的理由是逐字稿說的，不是我補的合理解釋？
- [ ] **數字**：日期、梯次、金額、人數是逐字稿說的？
- [ ] 沒有把別場次的內容搬到本場？
- [ ] 沒有把「沒有特別回報」寫成「均已完成」？
- [ ] 沒有把「還要有人去認定」寫成決議？
- [ ] 沒有把討論中的提議寫成「建議」或「結論」？
- [ ] 判不出來的都標了「待確認」？
- [ ] 沒有把「希望」寫成「須」、「建議」寫成「決議」？
- [ ] 沒有把已被否定的時程寫成計畫（逐字稿回「來不及了」者，改寫「後續」）？
- [ ] 辨識不清的單位名沒有用常識填空？

**被退過的實例**：把 8/6 的 API Key 寫進 9/3 的帳號設定；「銀行設備均已安裝完成」；
委外報備具名到葛世豪；委外三要件寫成決議；把 Kevin 老師對應到授課段落（逐字稿全篇無 Kevin）。

## B. 選材

- [ ] 每一項本次都有新進展？
- [ ] 沒有無結論又無下一步的項目？
- [ ] 沒有承辦內部作業、執行細節、工具排錯、評價語？
- [ ] 沒有寫「本次未討論」？
- [ ] 壓縮比合理（逐字稿萬字級 → 定稿數百字）？

## C. 定位

- [ ] 既有案件案名與 `registry/案件索引.md` 一致，沒有自行改名？
- [ ] 「新增議題」裡的每一項都真的是本次新冒出、尚未進看板？
- [ ] 空節沒有出現？
- [ ] 負責人依案件歸屬而非當日出席，請假者仍標名？

## D. 成文

- [ ] 每則是因果鏈，不是並列事實堆疊？
- [ ] 沒有記「誰主張什麼」？
- [ ] 沒有解釋技術機制（改寫成待釐清的問題）？
- [ ] 沒有寫誰退件、第幾版、誰不同意？
- [ ] 無結論的項目直接寫下一步，沒有贅寫「本項尚無結論」？
- [ ] 「請……」的項目都是當場有人承接且已定案？
- [ ] 每則一至三句？

## E. 體例

- [ ] 標點全形、括號半形、無破折號？
- [ ] 月份日期用阿拉伯數字（10月初）？「紀錄」非「記錄」？「二位」非「兩位」？
- [ ] 沒有分類小標（現況／結論／前提／時程／痛點）？
- [ ] 人名、專名已依 `registry/名詞校正表.md`、`registry/人物與組織.md` 校正？
- [ ] 敏感詞已去識別（境外模型、海外子行、採租賃的電腦設備、金控董事長）？
- [ ] 郵件外框前後套語齊全？

## F. 交付

- [ ] 會議時間、與會人員缺漏處標了「待補」？
- [ ] 草稿已存入 `minutes/`？
- [ ] 對話中完整呈現全文？
