# 撰寫體例

## 一、文件結構

郵件外框固定：

```
各位主管好：

檢送{YYYY/M/D(週別)}「{完整會議名稱}」會議紀錄，敬請參閱。

（本文）

若有任何問題，再請聯繫我，謝謝！

Best,
```

本文三個大項固定：

- **壹、會議時間**：`2026/9/3(四)PM4:00-5:00`。日期按雙週週四推算，結束時間逐場問。
- **貳、與會人員**：名單沿用前次，每場只更新出席狀態。請假者仍列名並標 `(請假)`，
  必要時寫原因 `歐黛瑩(會議衝堂請假)`。
- **參、討論議題與會議紀要**，底下三節，視內容取捨，空節整節不出現：

| 節 | 收什麼 |
| --- | --- |
| 一、本次主議題 | 有邀請單位列席、或當次集中處理的大事（行前訓練、工作坊執行協調） |
| 二、各案進度 | Loop 看板既有案件，案名照看板 |
| 三、新增議題 | 本次**新成案**、將進任務追蹤表追蹤者 |
| 三、討論議題 | 本次僅**討論、尚未成案**者；不入任務追蹤表 |

「新增議題」與「討論議題」擇一或並列，依該事項本次是否成案而定。
判準：成案（有人承接、將進追蹤表）→ 新增議題；仍在評估、未定是否辦理 → 討論議題。
討論議題只寫到「將做什麼」為止，討論中的具體做法不寫成決議。

編號層級：壹貳參 → 一二三 → 1. 2. → (1) (2)。
**不下「現況」「結論」「前提」「時程」「痛點」這類分類小標**，一律 by 事件。

## 二、句式：一條因果鏈

每則一至三句，走完「已經到哪 → 卡在哪／為什麼 → 接下來做什麼 → 為了什麼」：

> 三長已於8月會議同意個資上傳至企業受控雲端環境無虞，**惟**資料經LLM Gateway上送時仍會遮蔽，
> **故擬**透過資料分級自源頭界定可上送範圍，**作為**放寬遮蔽限制之依據。

> 與法遵單位討論已告一段落，策略面細節**俟**三長確認後定案，**將**安排會議並一併報告SPADE現行走向。

> 承辦所提第二版經張老師退回，主因框架邏輯未臻一致，**後續**由PMO協助對焦調整。

**不是**並列事實堆疊（A是X；B是Y；C是Z）。
**不記**誰主張什麼、誰反對什麼；只寫事情會怎麼走。
**不解釋**技術機制，只寫卡在哪。

## 三、語體

行政文書體。正式動詞優先：已／業已／刻正／俟／惟／擬／另／尚待／將。

**時態以定稿撰寫時點為準**：紀錄於會後數日始定稿，會中稱「下週一」之事若已發生，
寫「已於週一(9/21)報告」，不沿用會中的未來式。
無主詞時以書面動詞起句：已建立、已完成、尚待、將安排。

| 退掉的 | 改成 |
| --- | --- |
| 交辦管道眾多，導致資訊碎片化 | 專案推動涉及多元溝通與交辦管道 |
| 避免漏接交辦事項 | 定期彙整重要事項、同步執行進度 |
| 自己放 | 請各位自行新增 |
| 先把檔案丟入群組 | 可先將檔案於群組中分享 |
| 二度未獲採納 | 經退回，主因……，後續由PMO協助對焦調整 |
| 就看你們要什麼時候寄 | 不寫（無結論） |
| 承辦所提第二版經張老師退回 | 目前版本框架邏輯仍未臻一致 |
| 銀行架構審議認有必要、張老師認短期尚無需求 | 不寫（改直接寫將採取的行動） |
| 替代方案改以介接方式依登入者權限取資 | 該替代方案是否落入此範圍，屆時一併釐清 |

三條用詞原則：

1. 問題診斷改正面表述（漏接 → 彙整；分歧 → 一致）
2. 管控語彙改協作語彙（追蹤機制 → 同步機制）
3. 不寫削弱義務的表述（「並採開放參加性質」被刪）
4. **不究責、不寫版次**：不寫誰退件、第幾版、誰不同意；改為陳述目前狀態或將採取的行動
5. **機制說明改寫成待釐清的問題**：不解釋替代方案怎麼運作，寫「是否落入此範圍，屆時一併釐清」

## 四、交辦句式的前提

主議題節可用「請……」，但前提是**當場有人承接、事情已定案**。
沒到這一步就寫陳述式（已／將／待／尚待）。**紀錄沒有立場指派工作。**

## 五、負責人標註

依案件歸屬，不依當日出席（請假者仍標名）。判不出歸屬就不標。

- 單人 `(邱錦瑩)`
- 多人 `(唐可芹、劉宜依)`
- 分工不同 `(柯燕茹/黃啟龍)`
- (1)(2) 子項可只在其中一項標註，或統一標在案名後

## 六、體例硬規則

- 標點全形（逗號、分號、冒號、句號）；括號半形
- 不用破折號「——」，改用句號、逗號或冒號重組
- 標題不出現評價語（「高風險」「危機」）
- 專有名詞保留英文原樣：SPADE、API Key、Token、POC、agent、LLM、LLM Gateway、
  pre-production、M365、Copilot、SharePoint、webmail、Slack、Teams
- **月份日期用阿拉伯數字**：10月初，不寫「十月初」
- 用「紀錄」不用「記錄」（名詞）
- 單位用正式簡稱：數科處，不寫「數位科技單位」
- 數量用「二位」「三長」，不寫「兩位」
- 負責人判不出時，於案名後標「（負責人待確認）」

## 七、里程碑

供任務追蹤表用，不在紀錄正文逐一列出核決關卡。正文只留：

- 有日期的節點（8/28 討論、12月公告）
- 排程限制的實質原因（「科技運用管理委員會非定期召開，各階段時程須提前規劃」）

不寫「須注意里程碑時程」這種沒有依據的提醒。
